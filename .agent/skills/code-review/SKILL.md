# Code review

This skill is used to perform an in-depth code review, checking for code quality, performance, and other issues. The code review must focus on correctness of the code and respect to the surrounding coding style.

## When to use this skill

- Use this when the user explicitly requests a code review.
- This is helpful for the user to get feedback on their code.

## Review checklist

1. Identify the code snippets or files that need to be reviewed. Focus on the code that is most relevant to the user's request and the code that is modified but not yet committed.
2. Analyze the code for logical correctness, performance bottlenecks, and adherence to the project's coding style.
3. Provide specific, actionable feedback and suggestions for improvement.
4. Suggest alternative solutions or approaches if appropriate.
5. **Correctness**: Does the code do what it's supposed to?
6. **Edge cases**: Are edge cases for functionality handled?
7. **Style**: Does it follow project conventions?
8. **Performance**: Are there obvious inefficiencies?

## How to provide feedback

- Be specific about what needs to change
- Explain why, not just what
- Suggest alternatives when possible
